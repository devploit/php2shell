## Per-build notes

### PHP 8.5.11 — RCE verified

`php:8.5.11-apache`, bookworm, mod_php prefork, one worker, `display_errors=On`,
`memory_limit=8M`. The factory reproduced the full chain:

```text
[*] stage1 probe: stale block taken by v0841
    N=841 len=63 -> cookie=4096 chunk=0xffff8f000000
[*] stage2 T=406 -> libphp=0xffff8bc00000
[+] stage3 0x690d8/bookworm: uid=33(www-data) ...
[*] rce=True
```

This is the 8.5 branch, fixed in 8.5.12.

### PHP 8.4.26 deb13/apxs2 — RCE reported on a source build

`php-8.4.26-deb13-apxs2-amd64` is a Debian 13 source build (Apache 2.4.69,
apxs2, prefork, one worker), not an official image. It needs a third stage-3
layout: five `(4,4)` pads shift the bin-56 reclaim slot so a 31-byte fake
reference lands whole at R0. Stages 1-2 dispatch cleanly on every attempt;
stage 3 is instance-dependent, so retry on a fresh master. The profile must be
selected explicitly (`--profile deb13-apxs2`) because the official 8.4.26
bookworm profile has the same PHP version and architecture.

### PHP 8.4.26 — RCE verified

`php:8.4.26-apache`, bookworm. Verified 3/3 manually and through the factory.
Fixed in 8.4.27. This is the profile used against the local 8.4.26 laboratory.

### PHP 8.3.35 — leaks only

`php:8.3.35-apache`. Stage 1 (heap base) and stage 2 (libphp base) reproduce;
stage 3 does not place the fake reference. `rce=false`. Fixed in 8.3.36.

### PHP 8.3.33 — leaks only

`wordpress:7.1.1-apache` (PHP 8.3.33, mod_php). Stages 1-2 reproduced; stage 3
not calibrated. Fixed in 8.3.36.

### PHP 8.2.34 — calibration failed

`php:8.2.34-apache`. The libphp offsets were extracted
(0x36ff48 / 0x4606c0), but the 8.4/8.5 upload-progress leak shape did not
reproduce: the stage-1 probe did not reveal the stale-block index and stage 2
found no libphp pointer. `rce=false`, no heap parameters.

## Coverage vs the catalog

`catalog/vulnerable.json` lists every branch from the advisory matrix
(5.4 → 8.5, plus 8.6 RC). The profiles above cover the representative official
images that were actually run. A version is exploitable only when a verified
profile exists for its exact build; the dispatcher refuses to guess.

To add a build, append it to `BUILDS` in `tools/php2shell_matrix.py` and run the
factory. Architecture matters: these profiles are `aarch64`; an `x86_64`
image produces its own offsets and heap layout.
